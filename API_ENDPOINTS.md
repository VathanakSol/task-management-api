# Task Management API — Endpoint Reference

Base URL for local development: `http://127.0.0.1:8000`

All request and response bodies are JSON. The API has no authentication in this version and must not be exposed to an untrusted network without adding appropriate controls.

## Start the API

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
uvicorn app.main:app --reload
```

FastAPI also provides interactive documentation at `/docs` and the OpenAPI schema at `/openapi.json`.

## Task model

| Field | Type | Rules |
|---|---|---|
| `id` | integer | Generated by SQLite; response only |
| `title` | string | Required on create; trimmed; 1–200 characters; cannot be blank |
| `description` | string or null | Optional; maximum 2,000 characters |
| `status` | string | `todo`, `in_progress`, or `done`; defaults to `todo` |
| `due_date` | string or null | Optional ISO date in `YYYY-MM-DD` format |
| `created_at` | string | UTC timestamp; response only |
| `updated_at` | string | UTC timestamp; response only |

Example task:

```json
{
  "id": 1,
  "title": "Review pull request",
  "description": "Check tests and API documentation",
  "status": "todo",
  "due_date": "2026-12-31",
  "created_at": "2026-01-15T10:30:00.000000Z",
  "updated_at": "2026-01-15T10:30:00.000000Z"
}
```

## 1. Health check

`GET /health`

Returns `200 OK`:

```json
{"status": "ok"}
```

This checks that the application responds; it does not perform a database connectivity check.

## 2. Create a task

`POST /tasks`

Only `title` is required. Omitted optional fields use their defaults.

```bash
curl -i -X POST 'http://127.0.0.1:8000/tasks' \
  -H 'Content-Type: application/json' \
  -d '{"title":"Review pull request","description":"Check tests","status":"todo","due_date":"2026-12-31"}'
```

Returns `201 Created` with the complete task. Invalid fields return `422 Unprocessable Entity`.

## 3. List tasks

`GET /tasks`

| Query parameter | Default | Validation |
|---|---:|---|
| `status` | none | Optional: `todo`, `in_progress`, or `done` |
| `limit` | `100` | Integer from 1 through 100 |
| `offset` | `0` | Integer greater than or equal to 0 |

```bash
curl 'http://127.0.0.1:8000/tasks?status=todo&limit=20&offset=0'
```

Returns `200 OK` with an array ordered by descending task ID (newest first). An empty result is `[]`, not a 404. Pagination metadata is not included.

## 4. Get one task

`GET /tasks/{task_id}`

`task_id` must be an integer greater than or equal to 1.

```bash
curl 'http://127.0.0.1:8000/tasks/1'
```

Returns `200 OK` with the task, or `404 Not Found` when it does not exist.

## 5. Replace editable fields

`PUT /tasks/{task_id}`

`title` is required. `description` and `due_date` may be null; omitted optional fields receive their schema defaults. `status` defaults to `todo` when omitted. Include the complete desired representation to avoid resetting fields.

```bash
curl -X PUT 'http://127.0.0.1:8000/tasks/1' \
  -H 'Content-Type: application/json' \
  -d '{"title":"Review updated pull request","description":"Re-run tests","status":"in_progress","due_date":"2026-12-31"}'
```

Returns `200 OK` with the updated task, `404` if absent, or `422` for invalid input.

## 6. Partially update a task

`PATCH /tasks/{task_id}`

Supply at least one editable field. Omitted fields remain unchanged. Explicit `null` clears `description` or `due_date`.

```bash
curl -X PATCH 'http://127.0.0.1:8000/tasks/1' \
  -H 'Content-Type: application/json' \
  -d '{"status":"done"}'
```

Returns `200 OK` with the updated task. An empty object returns `422`; an absent task returns `404`.

## 7. Delete a task

`DELETE /tasks/{task_id}`

```bash
curl -i -X DELETE 'http://127.0.0.1:8000/tasks/1'
```

Returns `204 No Content` with an empty response body. A missing task returns `404`.

## Errors

Validation failures use FastAPI's standard structure. Exact messages can vary by dependency version.

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "title"],
      "msg": "String should have at least 1 character",
      "input": ""
    }
  ]
}
```

A missing task returns:

```json
{"detail": "Task not found"}
```

| Status | Meaning |
|---|---|
| `404` | Task ID does not exist |
| `422` | Invalid JSON body, field, path parameter, or query parameter |

## Browser testing console

Open `api-preview.html` in the project preview. **Demo mode** stores sample tasks only in your browser and does not call the API. **Live API mode** sends real requests to the configured base URL; create, update, and delete requests change that API's database.

For live mode, start uvicorn as shown above. If the browser reports a CORS error, use the console from the same origin or add a narrowly configured FastAPI `CORSMiddleware` for local development. Do not use a wildcard origin with credentials in production.

## Automated tests

```bash
pytest -q
```

Tests use a temporary SQLite database per test. Test execution is environment-dependent; this document does not claim a test result unless it was actually run.
